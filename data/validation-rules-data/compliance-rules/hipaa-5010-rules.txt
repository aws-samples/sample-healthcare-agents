# HIPAA 5010 X12 837P Compliance Rules

## General Compliance Requirements
- All claims must follow HIPAA 5010 X12 837P format specifications
- Electronic claims must be submitted via approved clearinghouse or direct connection
- Protected Health Information (PHI) must be encrypted in transit and at rest
- Business Associate Agreements required for all third-party processors
- Audit trails required for all claim submissions and modifications
- Retention period: minimum 6 years for claim records

## Required Data Elements (HIPAA 5010)
- Submitter Name and Identifier
- Receiver Name and Identifier
- Transaction Set Control Number (unique per claim)
- Hierarchical Level Code
- Subscriber Information (name, ID, DOB, gender, address)
- Patient Information (if different from subscriber)
- Billing Provider Information (NPI, name, address, tax ID)
- Rendering Provider Information (NPI, name)
- Service Facility Location (when different from billing provider)
- Diagnosis Codes (ICD-10-CM format, minimum 1)
- Procedure Codes (CPT/HCPCS format)
- Service Dates (from and to dates)
- Place of Service Code
- Charge Amount
- Units of Service

## Format Validations
- NPI must be 10 digits
- Tax ID (EIN) must be 9 digits in format XX-XXXXXXX
- Member ID format varies by payer but must not contain special characters
- Dates must be in CCYYMMDD format
- Currency amounts must be in format with 2 decimal places
- Diagnosis codes must be valid ICD-10-CM codes (3-7 characters)
- Procedure codes must be valid CPT (5 digits) or HCPCS (5 alphanumeric)
- Place of service must be valid 2-digit code (01-99)
- Modifiers must be valid 2-character codes

## Code Set Requirements
- ICD-10-CM diagnosis codes (effective October 1, 2015)
- CPT procedure codes (updated annually)
- HCPCS Level II codes for supplies and services
- Place of Service codes (CMS-maintained)
- Type of Service codes
- Taxonomy codes for provider specialties
- Relationship codes for patient-subscriber relationship

## Claim Validation Rules
- At least one diagnosis code required (maximum 12)
- At least one procedure code required per service line
- Service date must not be in the future
- Service date must be within timely filing limits
- Charges must be greater than zero
- Units must be greater than zero
- Rendering provider must have valid NPI
- Billing provider must have valid NPI and Tax ID
- Patient must have valid insurance coverage on date of service
- Diagnosis codes must support medical necessity for procedures

## Loop and Segment Requirements
- Loop 2000A: Billing Provider Hierarchical Level (required)
- Loop 2000B: Subscriber Hierarchical Level (required)
- Loop 2010AA: Billing Provider Name (required)
- Loop 2010AB: Pay-to Provider Name (if different)
- Loop 2010BA: Subscriber Name (required)
- Loop 2010BB: Payer Name (required)
- Loop 2300: Claim Information (required)
- Loop 2400: Service Line Information (required, repeating)
- Segment CLM: Claim Information (required)
- Segment REF: Reference Identification (conditional)
- Segment HI: Health Care Diagnosis Code (required)
- Segment SV1: Professional Service (required per line)

## Data Quality Requirements
- No leading or trailing spaces in data fields
- Consistent use of uppercase for text fields
- Valid state codes (2-character postal abbreviations)
- Valid country codes (ISO 3166-1)
- Phone numbers in format XXX-XXX-XXXX
- ZIP codes in format XXXXX or XXXXX-XXXX
- Consistent date formats throughout claim
- Consistent provider identifiers throughout claim

## Security and Privacy Requirements
- Minimum necessary standard for PHI disclosure
- Patient authorization for non-TPO uses
- Accounting of disclosures maintained
- Access controls for claim data
- Encryption of electronic transmissions
- Secure storage of claim records
- Breach notification procedures in place
- Business Associate Agreements executed

## Transaction Standards
- Version: 005010X222A1 (837P Professional)
- Implementation Guide: ASC X12N 837 (005010X222A1)
- Companion Guide: Payer-specific requirements
- Acknowledgment: 999 Implementation Acknowledgment
- Claim Status: 277 Claim Status Response
- Remittance: 835 Electronic Remittance Advice

## Common Rejection Reasons
- Invalid or missing NPI
- Invalid or missing diagnosis codes
- Invalid or missing procedure codes
- Service date outside coverage period
- Duplicate claim submission
- Missing prior authorization
- Invalid place of service
- Missing or invalid modifiers
- Charges do not match units
- Missing required provider information
